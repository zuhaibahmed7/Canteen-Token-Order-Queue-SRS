## 📌 Project Overview

This project presents a complete **Software Requirements Specification (SRS)** for a **Canteen Token and Order Queue Management System** — a solution designed to eliminate long queues, reduce wait times, and streamline food ordering in a university canteen environment.

Instead of students crowding the counter, the system allows them to place orders digitally, receive a token number, and get notified when their order is ready.

## 📋 SRS Deliverables Covered

### Part A — Requirements
- ✅ Problem Statement (5–8 lines) + Actors List
- ✅ Functional Requirements (8–12 bullet points) — written as "System shall..."
- ✅ Non-Functional Requirements (6–8 bullet points) — security, performance, usability, availability
- ✅ Out of Scope (3–5 bullet points)

### Part B — Design Diagrams
- ✅ Use Case Diagram + 3 Use Case Descriptions (3 important flows)
- ✅ Architecture Diagram — Component View (UI → Backend → Database)
- ✅ Class Diagram — 5–8 core entity classes
- ✅ Sequence Diagram — 1 main flow (e.g., Place Order / Generate Token)
- ✅ Deployment Diagram — Client + Server + Database

---

## 🎯 Problem Being Solved

University canteens face serious congestion during break hours. Students waste time standing in queues instead of eating. This system proposes a **token-based digital queue** where:

- Students browse the menu and place orders via a simple interface
- A unique token number is generated per order
- The canteen staff processes orders in sequence
- Students are notified when their order is ready for pickup
